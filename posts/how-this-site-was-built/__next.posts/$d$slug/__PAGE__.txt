10:T2433,<p>开一个新站最费时间的从来不是写代码，是决定「用什么写」。这篇把当时的取舍记下来，省得以后自己都忘了。</p>
<h2 id="为什么是静态导出">为什么是静态导出</h2>
<p>这个站没有任何需要服务端的东西：没有登录、没有数据库、没有实时数据。所有内容在构建时就确定了。</p>
<p>所以直接开静态导出：</p>
<pre class="shiki synthwave-84" style="background-color:#262335;color:#bbbbbb" tabindex="0"><code><span class="line"><span style="color:#848BBD;font-style:italic">// next.config.ts</span></span>
<span class="line"><span style="color:#FEDE5D">const</span><span style="color:#FF7EDB"> nextConfig</span><span style="color:#FEDE5D">:</span><span style="color:#FE4450"> NextConfig</span><span style="color:#FFFFFFEE"> =</span><span style="color:#BBBBBB"> {</span></span>
<span class="line"><span style="color:#FF7EDB">  output</span><span style="color:#B6B1B1">:</span><span style="color:#FF8B39"> "export"</span><span style="color:#BBBBBB">,        </span><span style="color:#848BBD;font-style:italic">// 构建产物是 out/</span></span>
<span class="line"><span style="color:#FF7EDB">  images</span><span style="color:#B6B1B1">:</span><span style="color:#BBBBBB"> { </span><span style="color:#FF7EDB">unoptimized</span><span style="color:#B6B1B1">:</span><span style="color:#F97E72"> true</span><span style="color:#BBBBBB"> },</span></span>
<span class="line"><span style="color:#FF7EDB">  trailingSlash</span><span style="color:#B6B1B1">:</span><span style="color:#F97E72"> true</span><span style="color:#BBBBBB">,     </span><span style="color:#848BBD;font-style:italic">// 导出成 /about/index.html，兼容性好</span></span>
<span class="line"><span style="color:#BBBBBB">};</span></span></code></pre>
<p>好处很实在：</p>
<ul>
<li><strong>部署自由</strong>。产物就是一堆 HTML/CSS/JS，丢到 Vercel、Cloudflare Pages、GitHub Pages 还是自己的 nginx 都能跑，不会被某个平台绑住。</li>
<li><strong>省钱</strong>。静态托管的免费额度通常够用一辈子。</li>
<li><strong>快</strong>。没有服务端渲染的往返，首屏就是 HTML。</li>
</ul>
<p>代价也要说清楚：没有服务端就意味着<strong>不能有 API 路由、不能有 Server Actions、不能用 ISR</strong>。以后要是想加评论系统，得挂第三方（比如 Giscus）。</p>
<h2 id="为什么内容用-markdown-而不是-mdx">为什么内容用 Markdown 而不是 MDX</h2>
<p>MDX 很诱人：能在正文里直接写 React 组件。但它把<strong>内容格式和框架版本绑死了</strong> —— MDX 的编译器和 React 版本强耦合，升级框架时正文有可能集体编译失败。</p>
<p>对一个要放很多年的个人站来说，这个风险不划算。所以用最朴素的方案：</p>
<pre class="shiki synthwave-84" style="background-color:#262335;color:#bbbbbb" tabindex="0"><code><span class="line"><span style="color:#36F9F6">unified</span><span style="color:#BBBBBB">()</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">remarkParse</span><span style="color:#BBBBBB">)</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">remarkGfm</span><span style="color:#BBBBBB">)</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">remarkRehype</span><span style="color:#BBBBBB">, { </span><span style="color:#FF7EDB">allowDangerousHtml</span><span style="color:#B6B1B1">:</span><span style="color:#F97E72"> true</span><span style="color:#BBBBBB"> })</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">rehypeSlug</span><span style="color:#BBBBBB">)</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">rehypeShiki</span><span style="color:#BBBBBB">, { </span><span style="color:#FF7EDB">theme</span><span style="color:#B6B1B1">:</span><span style="color:#FF8B39"> "synthwave-84"</span><span style="color:#BBBBBB"> })</span></span>
<span class="line"><span style="color:#BBBBBB">  .</span><span style="color:#36F9F6">use</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">rehypeStringify</span><span style="color:#BBBBBB">, { </span><span style="color:#FF7EDB">allowDangerousHtml</span><span style="color:#B6B1B1">:</span><span style="color:#F97E72"> true</span><span style="color:#BBBBBB"> });</span></span></code></pre>
<p>产出的是纯 HTML 字符串，跟 React 什么版本毫无关系。想加新语法就加插件，不想用了就删掉，正文一个字都不用动。</p>
<blockquote>
<p>内容比框架活得久。让内容依赖框架的实现细节，是给自己埋雷。</p>
</blockquote>
<h2 id="毛玻璃是怎么做的">毛玻璃是怎么做的</h2>
<p>关键只有一行：</p>
<pre class="shiki synthwave-84" style="background-color:#262335;color:#bbbbbb" tabindex="0"><code><span class="line"><span style="color:#FEDE5D">.card</span><span style="color:#BBBBBB"> {</span></span>
<span class="line"><span style="color:#72F1B8">  backdrop-filter</span><span style="color:#B6B1B1">:</span><span style="color:#FE4450"> blur</span><span style="color:#BBBBBB">(</span><span style="color:#F97E72">18px</span><span style="color:#BBBBBB">) </span><span style="color:#FE4450">saturate</span><span style="color:#BBBBBB">(</span><span style="color:#F97E72">150%</span><span style="color:#BBBBBB">);</span></span>
<span class="line"><span style="color:#BBBBBB">}</span></span></code></pre>
<p>但<strong>毛玻璃必须有东西可以「透」</strong>。如果背景是一片纯色，模糊前后完全一样，效果等于没有 —— 这是很多人做毛玻璃翻车的原因。</p>
<p>所以底下铺了一层极光：几个大幅模糊的彩色球体在缓慢漂移。</p>
<pre class="shiki synthwave-84" style="background-color:#262335;color:#bbbbbb" tabindex="0"><code><span class="line"><span style="color:#FEDE5D">.aurora-blob</span><span style="color:#BBBBBB"> {</span></span>
<span class="line"><span style="color:#72F1B8">  position</span><span style="color:#B6B1B1">:</span><span style="color:#FE4450"> absolute</span><span style="color:#BBBBBB">;</span></span>
<span class="line"><span style="color:#72F1B8">  border-radius</span><span style="color:#B6B1B1">:</span><span style="color:#F97E72"> 999px</span><span style="color:#BBBBBB">;</span></span>
<span class="line"><span style="color:#72F1B8">  filter</span><span style="color:#B6B1B1">:</span><span style="color:#FE4450"> blur</span><span style="color:#BBBBBB">(</span><span style="color:#F97E72">90px</span><span style="color:#BBBBBB">);</span></span>
<span class="line"><span style="color:#72F1B8">  animation</span><span style="color:#B6B1B1">:</span><span style="color:#BBBBBB"> drift </span><span style="color:#F97E72">26s</span><span style="color:#FE4450"> ease-in-out</span><span style="color:#FE4450"> infinite</span><span style="color:#BBBBBB">;</span></span>
<span class="line"><span style="color:#BBBBBB">}</span></span></code></pre>
<p>有了彩色的、会动的底，上面那层 <code>backdrop-filter</code> 才有意义。</p>
<h2 id="用-theme-inline-串起设计变量">用 @theme inline 串起设计变量</h2>
<p>Tailwind 4 允许把 CSS 变量注册成工具类：</p>
<pre class="shiki synthwave-84" style="background-color:#262335;color:#bbbbbb" tabindex="0"><code><span class="line"><span style="color:#FEDE5D">@theme</span><span style="color:#BBBBBB"> inline {</span></span>
<span class="line"><span style="color:#FF7EDB">  --color-sakura</span><span style="color:#B6B1B1">:</span><span style="color:#FE4450"> var</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">--c-sakura</span><span style="color:#BBBBBB">);</span></span>
<span class="line"><span style="color:#FF7EDB">  --color-violet</span><span style="color:#B6B1B1">:</span><span style="color:#FE4450"> var</span><span style="color:#BBBBBB">(</span><span style="color:#FF7EDB">--c-violet</span><span style="color:#BBBBBB">);</span></span>
<span class="line"><span style="color:#BBBBBB">}</span></span></code></pre>
<p><code>inline</code> 这个关键字是关键。不加它，Tailwind 会把变量的<strong>值</strong>抄进每个工具类；加上之后生成的是 <code>var(--c-sakura)</code> 引用 —— 运行时改变量就能整体换色，不用重新构建。</p>
