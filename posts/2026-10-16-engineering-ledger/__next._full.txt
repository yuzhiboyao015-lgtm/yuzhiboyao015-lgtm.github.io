<h2 id="三为什么样式会变成七千行">三、为什么样式会变成七千行</h2>
<p>因为它被当作<strong>施工日志</strong>在用。</p>
<p>一个文件里同时住着：设计变量（颜色、间距、毛玻璃参数）、基础排版、每个页面的私有布局、以及一百多处"覆盖某条规则"的补丁。</p>
<p>举例：<code>.post-shell</code> 这一段被改过十几遍，因为每加一个页面就要重新调它的内边距；<code>.about-name</code> 这个类在文件里出现了两次，第二次是覆盖第一次的。</p>
<p>坏处很明显：<strong>改一处要靠搜索确认没有副作用</strong>。好处也有：所有样式在一屏之内可查，不用在十几个模块之间跳来跳去。这是个权衡，不是我没想过拆。</p>

<h2 id="五依赖为什么只有十一个">五、依赖为什么只有十一个</h2>
<pre><code>next  react  react-dom
unified  remark-parse  remark-gfm  remark-rehype  rehype-stringify  rehype-slug
@shikijs/rehype  gray-matter
</code></pre>
<p>除了 Next 和 React 这一套，剩下全是<strong>把 Markdown 变成 HTML</strong> 的流水线：解析、扩展语法、转 HTML、给标题加锚点、给代码上色，最后一件事交给 <code>gray-matter</code> 读前言。</p>
<p>没有一个图标库——图标是手写的内联 SVG；没有一个动画库——动效是 CSS 关键帧；没有一个 UI 组件库——所有卡片都是自己写的 <code>div</code>。</p>
<p>这不是"极简主义"，是算术：<strong>每多一个依赖，就多一个人可以在半夜改坏你的站</strong>，也多一份要跟着升级的东西。</p>
<h2 id="六静态导出的账">六、静态导出的账</h2>
<p>构建是 <code>next build</code> + <code>output: "export"</code>，产物是一堆纯文件。这带来几笔很清楚的账：</p>
<p><strong>赚的：</strong></p>
<ul>
<li>不需要服务器进程，也不怕它挂</li>
<li>全站没有一次数据库查询</li>
<li>页面是预渲染的 HTML，首屏不需要等 JS</li>
</ul>
<p><strong>付的：</strong></p>
<ul>
<li>没有服务端，就没有「实时」。所有内容改动都要重新构建</li>
<li>图片优化服务不可用，照片墙只能用原图（所以压缩必须在上传前做完）</li>
<li>预取的 RSC 请求在静态站上会拿到 404——无伤大雅，但控制台不太好看</li>
</ul>
<p>最后这笔账我认了。<strong>一个不会生病的小屋，值得放弃一点实时性</strong>。</p>
<h2 id="七所以时间花在哪儿了">七、所以时间花在哪儿了</h2>
<p>如果把 9,666 行和 7,232 行加起来，再除以九天，大概是每天两千行。这个数字毫无意义——因为删掉的行没被统计进去。</p>
<p>真实的时间分配更接近这样：</p>
<pre><code>重新构想版式   ████████████████
调数值         ████████████
写新功能       ████████
修 bug         ██████
写内容         ████
</code></pre>
<p><strong>最多的时间花在"把已经能跑的东西推倒重来"上</strong>。</p>
